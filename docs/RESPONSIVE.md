# 家长端响应式设计

本文记录家长端（React SPA，仓库根目录）在**横屏手机**与**宽屏（平板 / 桌面浏览器）**
下的适配方案、设计取舍与验证方式。

---

## 0. 原来的问题

改动前所有页面的最外层都是同一个类名组合：

```
min-h-screen pb-20 bg-gray-100
```

它没有任何宽度约束。于是：

| 症状 | 具体表现 |
| --- | --- |
| 通栏拉伸 | 1920px 的桌面上，正文和卡片一路铺到屏幕两边，一行文字能到 1800px 宽，几乎无法阅读 |
| 导航形态错误 | 底部导航 `fixed bottom-0 left-0 right-0` 横跨整个窗口，三个入口被拉到相距 600px；鼠标要横跨全屏才能点 |
| 九宫格不利用横向空间 | 功能磁贴固定 3 列，超宽屏下每格宽得离谱，右侧还留一大片空白 |
| 横屏手机被纵向空间卡死 | 视口只有 320–420px 高，页头 + 底部导航就吃掉约 100px，一屏放不下几条 |
| 对话框顶出屏幕 | 横屏矮视口下对话框比屏幕还高，标题和底部按钮同时不可见，且滚不动 |

---

## 1. 核心做法：`.page-shell`

**没有**给每个页面包一层 `max-w-*` 容器，而是在最外层容器上用**对称的 `padding-inline`**
把内容挤到中间：

```css
@media (min-width: 768px) {
  .page-shell { padding-inline: max(0px, calc((100% - 42rem) / 2)); }
}
@media (min-width: 1024px) {
  .page-shell { padding-inline: max(0px, calc((100% - 48rem) / 2)); }
}
```

为什么不用「包一层限宽容器」这个更直觉的方案：

> 页面里有大量 `bg-white` 的**整宽页头、分隔线、整宽锁定通栏**。一旦给内容包上限宽容器，
> 这些整宽背景会跟着变窄、两边露出灰底，观感像「卡片没铺满屏幕」。
> `padding-inline` 保住了整宽背景，又把文字行宽压到可读范围，
> 而且**不需要动任何页面的 JSX 结构** —— 只需把最外层那串 className 换成 `.page-shell`。

`max(0px, …)` 里的 `0px` 是关键：它保证窄屏下 padding 恰好为 0，
不会出现「手机上莫名两边留白」。

### 1.1 标题栏必须铺满（`--shell-pad` + 负 margin）

只给容器加 `padding-inline` 会带来一个副作用：**白底页头被一起挤窄了**，
桌面上那条白条只从内容列开始，看着像没铺满。标题栏应当始终是 100% 宽。

做法是「负 margin 抵消父级留白 + 自己补回等量留白」：

```css
.page-shell > .page-header {
  margin-inline: calc(-1 * var(--shell-pad));   /* 白底/分隔线通栏 */
  padding-inline: calc(var(--shell-pad) + 1rem); /* 标题文字仍与内容列对齐 */
}
```

只做前者的话标题会贴着侧栏边，和下面的卡片脱节；只做后者就是改之前的样子。

**这里有个必须用 `vw` 而不能用 `%` 的坑。** 留白原本写成
`padding-inline: max(0px, calc((100% - 42rem) / 2))`，但 `%` 会在
**使用它的那个元素**的包含块上重新解析 —— 页头拿到的不是父元素算出来的那个数：
父元素被 padding 挤窄后，内容宽度恰好等于 42rem，页头里同样的表达式算出来是 **0**，
负 margin 直接失效。所以留白改为用 `vw` 计算的 `--shell-pad`：

```css
@media (min-width: 768px) {
  .page-shell { --shell-pad: max(0px, calc((100vw - 42rem) / 2)); }
}
@media (min-width: 1024px) {
  /* 224px = 左侧栏宽度，与 BottomNav 的 w-56 / lg:pl-56 必须一致 */
  .page-shell { --shell-pad: max(0px, calc((100vw - 224px - 48rem) / 2)); }
  .page-shell.page-shell--immersive { --shell-pad: max(0px, calc((100vw - 48rem) / 2)); }
}
```

`vw` 与上下文无关，父子拿到同一个数，页头刚好铺到容器边界、不会溢出。
沉浸式页面不显示侧栏，所以要单独把 224px 加回来。

> 排查提示：`--shell-pad` 是 0 的视口（例如 1180px 平板，可用宽度 956px
> 已经小于 `--wide` 的 960px 上限）本来就无处可铺，
> 此时「页头宽度 == 内容列宽度」是**正确的**。测试里这条断言只在
> `pad > 8` 时才要求页头更宽。

三个变体：

| 变体 | 用途 |
| --- | --- |
| `.page-shell` | 默认，内容 42rem（≥768）/ 48rem（≥1024） |
| `.page-shell--wide` | 列数会跟着变多的页面（首页九宫格、插件卡片墙、洞察、选择应用），48rem / 60rem |
| `.page-shell--immersive` | 不显示导航的页面（答题页、媒体查看），不需要给底栏让位 |
| `.page-shell--center` | 加载态 / 错误态，单个居中块，不设行宽上限 |

## 2. 导航：一种数据，两种形态

`BottomNav` 用 CSS 渲染两套结构，靠断点切换 —— **不用 `useMediaQuery`**：
首帧就必须正确，JS 方案在纯 CSR 应用里一样会闪一下。

| 视口 | 形态 |
| --- | --- |
| <1024px | 底部固定栏（原样），但在稍宽的手机上 `max-w-md mx-auto` 居中，避免三个入口被拉散 |
| ≥1024px | 左侧竖排侧栏（224px），带 logo、当前项高亮、底部说明；鼠标不必横跨全屏 |
| 矮视口（`max-height:520px`） | 底栏高度 3.5rem → 2.75rem，图标 24px → 20px，文字 12px → 10px |

侧栏出现时主内容要用 `lg:pl-56` 让位 —— 宽度只在 `BottomNav` 里定义一次
（`SIDEBAR_WIDTH_CLASS`），`App.tsx` 引用同一个常量，避免两处写岔。

**只有确实显示导航时才让位**：登录页、答题页、媒体页是沉浸式的，
不然它们会平白缩进一条。

## 3. 横屏与矮视口

```
@media (max-height: 520px) { … }
```

横屏手机最缺的是**垂直**空间，所以这一档只动纵向、不动横向：

- `.page-shell` 底部让位 5.5rem → 4rem
- 页头 `py-3` → `py-2`（21 处页头统一）
- 对话框 `max-h` 收到 `calc(100vh - 1rem)`、内边距 `p-6` → `p-4`
- 登录页 logo 80px → 56px，标题区间距收紧

**对话框限高**是这一档里最要紧的修复：横屏下不限高会上下同时溢出，
标题和底部按钮一起消失，而且滚不动 —— 用户唯一能做的就是杀掉浏览器标签。

登录页另有一处细节：容器用「父元素 `flex-1` 不居中 + 子元素 `my-auto`」而不是
`items-center`。flex 布局里 `items-center` 在内容高于容器时会把**顶部裁掉且滚不到**，
横屏（可视高度 320–420px）正好会触发；`my-auto` 在空间不足时自动退化为顶部对齐。

## 4. 逐页的栅格改造

| 页面 | 改动 |
| --- | --- |
| 首页功能磁贴（九宫格） | `grid-cols-3` → `grid-cols-3 sm:grid-cols-4 lg:grid-cols-6` |
| 首页照片缩略图 | `grid-cols-3` → `grid-cols-3 sm:grid-cols-4 lg:grid-cols-6` |
| 插件管理卡片墙 | `grid-cols-2` → `grid-cols-2 sm:grid-cols-3 lg:grid-cols-4` |
| 媒体页栅格 | `grid-cols-2` → `grid-cols-2 sm:grid-cols-3 lg:grid-cols-4` |
| 答题页统计卡 | `grid-cols-2` → `grid-cols-2 sm:grid-cols-4` |
| 模式时段 24 小时格子 | 宽屏拆成「00–11 / 12–23」两栏并排（`lg:grid-cols-2`），一栏 24 行在桌面上要滚很久，而横向明明有大片空地 |
| 洞察页类型筛选条 | 保留 `overflow-x-auto`，但在 `lg` 上改为换行（`lg:flex-wrap`）—— 桌面用户不该为了点一个筛选去横向滚 |

## 5. 验证

### 5.1 浏览器视口矩阵（`npm run e2e:responsive`）

在 `scripts/browser-e2e.mjs` 里新增了 `responsive` 套件，复用同一套 CDP 客户端与登录流程。

**5 档视口 × 14 个页面**，每页 4 类断言：

| 视口 | 覆盖 |
| --- | --- |
| 竖屏手机 390×844 | 全量 14 页 |
| **横屏手机 844×390** | 全量 14 页（本次重点） |
| 平板横屏 1180×820 | 全量 14 页 |
| **桌面 1440×900** | 全量 14 页（本次重点） |
| 超宽屏 1920×1080 | 全量 14 页 |

| 断言 | 为什么这样断言 |
| --- | --- |
| **逐元素量右边界**，不允许超出视口 | 只看 `document.scrollWidth` 是**没用的**：应用在 body 上设了 `overflow-x: hidden`，横向溢出会被藏起来而不是消失，而那些被裁掉的内容恰恰是用户永远看不到的 |
| 内容列左右对称且不超过上限 | 直接量 `.page-shell` 的 `padding` 与 `clientWidth`，能抓到「通栏拉伸」这个真正的病 |
| **标题栏铺满整个可用宽度** | 直接量 `.page-shell` 与 `> .page-header` 的左右边界，要求两者对齐（±1px）；且在确实存在留白时页头必须**比内容列更宽**，否则说明负 margin 没生效 |
| 导航形态与断点一致 | 窄屏必须出底栏、宽屏必须出侧栏；沉浸式页面两种都不许出现 |
| 关键内容确实渲染 | 防止「限宽成功但内容被裁没了」这种反向失败 |
| 横向可滚动容器内的元素不算溢出 | 筛选条 chips 本来就该能滚，不排除会把真问题淹掉 |
| **测试自检** | 断言页面确实用了 `.page-shell`，且宽屏下内容**严格窄于**可用区域 —— 挡住「选择器写错、探针量了个空元素」这类假通过 |

实测内容列宽（首页）：

```
竖屏手机 390×844       视口  390px → 内容  390px 左右留白 0/0
横屏手机 844×390       视口  844px → 内容  768px 左右留白 38/38
平板横屏 1180×820      视口 1180px → 内容  956px 左右留白 0/0（左侧栏已占 224px）
桌面 1440×900        视口 1440px → 内容  960px 左右留白 128/128（左侧栏已占 224px）
超宽屏 1920×1080      视口 1920px → 内容  960px 左右留白 368/368（左侧栏已占 224px）
```

结果：**5 档视口 × 14 页全部通过**（每档 69 项）。

## 6. 顺带修掉的一个过期断言

`npm run e2e:parent` 里有一条 `展示今日已用时长` 断言 `/今日已使用\s*\d+\s*分钟/`。
首页在「模式 / 护眼 / 插件」那一轮改版后文案变成了「今日使用时长」+ 格式化时长
（例如 `1小时35分钟`），于是这条断言一直是失败的。

本次一并改成按新版式断言，但**仍然要求页面上出现真实时长数字**，
不是简单删掉或放宽成 `includes('时长')`。

## 7. 已知边界

- **只管家长端。** 管理后台本身就是桌面优先的密集表格界面，本次未改动
  （只跟着受益于 `dialog.tsx` 的限高）。
- **没有做「桌面端双栏」这种结构性改版**（例如左列表右详情的 master-detail）。
  当前是把移动端版式在宽屏上居中限宽 + 提高列数，改动面小、回归风险低。
  若以后要做真正的桌面信息密度，需要逐个页面重新设计，不是加几个断点能解决的。
- **断点只用了 `md`(768) / `lg`(1024) 两档**，没有为折叠屏、平板竖屏单独调。
  820×1180 这类尺寸走的是 `md` 档，实测表现正常（见 5.1）。
- **没有做打印样式**（`@media print`）。
